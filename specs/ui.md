# UI 界面与交互设计规范 (UI Specification)

沿用 02.chess / 03.chess_master / 04.Gomoku 的视觉骨架（顶部标题栏 / 中间主区 /
侧边面板 / 结算浮层 / 底部说明区块），针对**像素画面**、**难度参数卡**与
**逐次击破记录表**做定制。

与前作最大的不同：主区左侧不再是"木色棋盘 + Canvas 棋子"，而是一块
**256×240 的 FC 画面**，按整数倍放大后嵌在游戏机塑料外壳色的边框里。

## 2. 顶部标题与计数 (`#content-title`)

- **左侧 `#hits-counter`**（`.title-counter.hits-counter`）：本轮击破的气球数，
  配色用 `--color-score-positive`，`title` 提示"本轮击破的气球数"。
- **中间 `.title`**：「气 球 打 字」，下方 `.title-sub` 一行副标题。
- **右侧 `#miss-counter`**（`.title-counter.miss-counter`）：本轮按错的次数，
  配色用 `--color-score-negative`。

两个徽章在数值变化时有 `.bump` 动效（`js/ui/panel.js` 的 `bump()` 加类，
130ms 后移除）——这是画面外的即时反馈，因为击破/失误发生时玩家的视线在画布上。

## 3. 画面区与菜单遮罩

### 3.1 `.stage-area` / `#stage`

- `.stage-area` 是**可用空间的计算基准**：`ResizeObserver` 观察它，
  `fitStage()` 取它的 `getBoundingClientRect()` 减去 20px 内边距，交给
  `stage.resize()`。
- `stage.resize(w, h)` 里 `scale = max(1, min(4, floor(min(w/256, h/240))))`，
  然后设 `canvas.style.width/height`。**canvas 的 `width`/`height` 属性恒为
  256/240**，绝不被缩放改动。
- CSS：`image-rendering: pixelated`（`styles/components/stage.css`），
  外框用 `--color-board-frame` 的灰（token 名沿用 `--color-board-*`
  以保持跨项目一致，虽然这里包的不是棋盘）。

**为什么两个方向都要 clamp**：只按宽度算，14 寸屏上画面会顶出可视区；
`--stage-area-h: clamp(285px, 72vh, 960px)` 取到 72vh 是为了在 1080p 上够得着
3 倍（3×240 + 边距 ≈ 740px），再高就会挤掉侧栏和底部说明。

### 3.2 画布内的绘制顺序

`js/ui/stage.js` 的 `draw(state)` 严格按这个顺序：

```text
1. 天空        fillRect 铺满 256×240（--nes-sky）
2. 云          3 朵，水平漂移，位置只跟 state.clock 有关（装饰，不入 rules）
3. 地面        ★ 先于气球画：气球落地时压在坑上才自然
              逐列取 state.ground[c] 作为上沿：
                已掏穿(surface>=240) → 跳过，露出天空形成缺口
                上沿未被砸(<=209)    → 叠 3px 草皮 + 1px 深草
                泥土纹理            → 每 5px 一道深色短线
4. 气球        从大到小叠三层椭圆轮廓（选中白圈 → 1px 黑边 → 本体色）
              + 左上角高光 + 结(4×1,2×1) + 波浪线(5px) + 字符
5. 扬尘        （在小鸟之下）
6. 塌陷特效
7. 小鸟        从右侧屏外飞入，缓出曲线，3 帧扇翅膀
8. 炸开        8 个碎片按角度散开 + 前 1/3 的白闪光
9. HUD         最上层，盖住所有可能溢出的气球
```

**注意顺序里有两处刻意的设计**：

- 地面画在气球**之前**——否则气球落地时会被地面盖住，看不到"陷进坑里"的感觉；
- 特效按类型分四趟循环，而不是一趟——这样同类特效之间的层叠关系是稳定的，
  不会因为数组顺序变化导致小鸟忽然跑到扬尘下面。

### 3.3 顶部信息条 HUD

高 16px（`GEOMETRY.HUD_H`），黑底白字，用 5×7 点阵字模画：

```text
+---------------------------+-----------------------+
| SCORE 007   LV6   ACC 093% |        BASE [▣▣▢▢]   |
+---------------------------+-----------------------+
   ↑ 击破数(补零)  ↑ 档位      ↑ 正确率   ↑ 剩余额度
```

- `LV` 在 ≥7 档时用红球色（`--nes-balloon-0`）提醒"这是高难度"。
- **`BASE` 塌陷计是 HUD 上唯一的图形元素**：格子数 = `collapseLimit`，
  填满就结束。放在 HUD 上而不是只在侧栏，是因为"还剩几格"是决定生死的量，
  不该逼玩家离开画面去看侧栏。

### 3.4 多级菜单遮罩 (`#stage-options`)

浮于画布之上，五页，同一时刻只显示一页（`.menu-page` + `.hide` 切换）：

```text
① #menu-main   气球打字（玩法简介）           [开始练习] [玩法说明]
                            │
                ┌───────────┴───────────┐
                ▼                       ▼
② #menu-mode   选择练习模式            ⑤ #menu-help  玩法说明
                ┌──────────────────┐                 · 键盘只认字母数字
                │ 键位分区  ──────  │                 · 切到英文输入法
                │ 英文字母  ──────  │                 · 四种模式说明
                │ 英文单词  ──────  │                 · 反应时间会被记录
                │ 汉字拼音  ──────  │                 · 决定生死的是地面
                └──────────────────┘
                [下一步] [‹ 返回]
                            │
              选键位分区 ─────┴──── 选其它模式
                            ▼
③ #menu-keys   选择键位组（仅键位分区模式经过）
                ┌────┬────┬────┬────┬────┐
                │0 基准键·左手│1 基准键·右手│2 基准键·合练│3 上排·左手│4 上排·右手│
                ├────┼────┼────┼────┼────┤
                │5 上排·合练│6 下排·左手│7 下排·右手│8 下排·合练│9 全键盘│
                └────┴────┴────┴────┴────┘
                [组说明区 #group-desc]
                [下一步：选难度] [‹ 返回选模式]
                            │
                            ▼
④ #menu-level  选择难度
                ┌────┬────┬────┬────┬────┐
                │0 入门│1 新手│2 初学│3 熟练│4 上手│
                ├────┼────┼────┼────┼────┤
                │5 进阶│6 快速│7 高手│8 精英│9 大师│
                └────┴────┴────┴────┴────┘
                [参数说明区 #level-desc]
                [开始练习] [‹ 返回上一步]
```

**关键交互**：

- **「开始练习」进的是选模式页，不是直接开局**。直接开局等于把模式和难度锁死在
  默认档，那几个选择页就成了死页面。
- **「下一步」按模式分流**：键位分区先进「选键位组」，其它模式直接进「选难度」。
  难度页的「返回上一步」动态指向（`data-back` 在 `renderLevelDesc()` 里同步）：
  键位分区退回选组页，其它退回选模式页。
- 所有按钮文案都从 `Difficulty.MODES` / `Difficulty.KEY_GROUPS` /
  `Difficulty.LEVELS` 现生成，`index.html` 里**一行硬编码的档位/模式/组名都没有**。
- 选中项加 `.active` 类。`menu.setSelection({mode, level, group})` 由 `app.js`
  在开局时调用——否则用「重开本轮」或结算里的「再来一轮」开局后，菜单里高亮的
  还是上一次手选的那个模式/组/档位，和实际在玩的对不上。

### 3.5 难度参数说明区 (`#level-desc`)

把当前档位的旋钮值**原样摆出来**。这是「诚实」原则的一部分：难度不是黑箱，
玩家能看到自己面对的是什么。

```text
英文字母 · 快速
单字气球下落 4.8s（目标每多 1 个字符补 0.55s）
出球间隔 780ms · 同屏上限 6 个
地面塌陷 4 列即结束
可用字母 26 个（按词频从高到低解锁）
```

## 4. 画布下方提示条 (`.stage-hint`)

一行两个信息：

- 键位提示：`键盘输入：A–Z / 0–9（大小写均可）`，用 `<kbd>` 元素；
- `#hint-audio`：音效状态。初始「待启用」，首次用户手势 `unlock()` 成功后变成
  「音效：已启用」；点静音按钮或 `?mute=1` 时显示「音效：已静音」。
  这个回显存在的意义是让"为什么没声音"变成一眼可查的事。

## 5. 侧栏 (`.side-panel`)

三张 `.panel-card`，宽度 `--panel-width: clamp(430px, 26vw, 560px)`。

### 5.1 ① 本轮信息

```text
+---------------------------------------+
| 本轮信息                                |
|  模式      英文单词                      |
|  难度      6 快速                       |
|  用时      12.4 s                       |
|  击破      7                            |
|  失误      2                            |
|  正确率    93.9%     ← .strong 加粗     |
|  速度      53 字/分                      |
|                                         |
|  地面塌陷                    1 / 4 列    |
|  [▣ ▢ ▢ ▢]                              |
|                                         |
|  [重开本轮] [菜单] [静音]                 |
+---------------------------------------+
```

- `<dl class="info-grid">` 的 `dt/dd` 结构，值全部来自 `state.stats`。
- **正确率在无输入时显示「—」而不是 100%**：不编造一个还没发生的数字。
- **塌陷进度条**：格子数 = `collapseLimit`，已塌陷的加 `.gone` 类。
  `panel.js` 只在**格子数变化**时重建 DOM，只在**已塌陷数变化**时改类名——
  侧栏每帧都刷新，不做这两层缓存就是白干活。
- 三个按钮：
  - `#restartbtn` **重开本轮** — 沿用 `current` 里的模式/键位组/档位；
  - `#menubtn` **菜单** — 暂停并打开菜单遮罩；
  - `#mutebtn` **静音** — 切换文案在「静音」/「取消静音」之间。

### 5.2 ② 击破记录（数据诚实的落点）

```text
+-----------------------------------------------+
| 击破记录                                        |
| 每一次击破的反应时间都是当场测出来的，逐条列出、   |
| 不挑好看的展示。慢于本条可用时间 60% 的记录标黄。  |
|  +----+------+-------+----------------+------+  |
|  | #  | 时刻 | 目标  | 反应            | 判定 |  |
|  +----+------+-------+----------------+------+  |
|  | 12 | 8.3s | TODAY | 412ms / 4800ms | 击破 |  |
|  | 11 | 6.1s | 学    | 3901ms / 5200ms| 击破 |←黄 |
|  | 10 | 5.2s | X     | —              | 失误 |  |
|  +----+------+-------+----------------+------+  |
|                     [当前状态条]                |
+-----------------------------------------------+
```

**「慢」的判定基准是每个气球自己**：`reactionMs > limitMs * SLOW_RATIO`
（`SLOW_RATIO = 0.6`，同气球各自比各自的，不是拿一个全局常数去卡）。
阈值写在 `js/ui/panel.js` 并导出，页面上的说明文案直接引用它——
**两边不会说岔**（`#slow-threshold` 的文本由 JS 用同一个常量填）。

- 行类名：`miss`（失误，红调）/ `slow`（慢，黄调）/ 默认。
- 表格只显示最近 `MAX_ROWS = 60` 条（`rules` 最多留 200 条）。
- **只在 `log.length` 变化时重绘**，新记录在最上面。
- `limitMs` 是气球从生成到落地一共给了玩家多少毫秒，
  由 `rules.js` 在击破时按 `(GROUND_TOP - SKY_TOP - totalH) / vy * 1000` 算出。

### 5.3 ③ 难度参数

与菜单的 `#level-desc` 同源（都调 `Difficulty`），但这里是**开局后**的实际生效值，
由 `panel.setFacts(lv, cfg, mode)` 填。六个字段逐行列出，数值加 `<b>`。

## 6. 结算浮层 (`#game-summary`)

```text
+-----------------------------------------------+
|                 本轮结束                        |
|                    中                          |  ← .summary-grade
|  +---------------------+---------------------+ |
|  | 模式                 | 英文单词             | |
|  | 难度                 | 6 快速               | |
|  | 用时                 | 52.3 s               | |
|  | 击破气球             | 6 个                 | |
|  | 击破字数             | 46 字                | |
|  | 最高连击             | 6 连                 | |
|  | 正确按键             | 46 次                | |
|  | 失误                 | 3 次                 | |
|  | 正确率               | 93.9%                | |
|  | 速度                 | 53 字/分             | |
|  | 平均反应             | 2647 ms              | |
|  | 最快反应             | 1467 ms              | |
|  | 落地漏球             | 29 个                | |
|  | 地面塌陷             | 4 / 4 列             | |
|  +---------------------+---------------------+ |
|   共击破 6 个目标、46 个字，平均反应 2647ms，    |
|   地面被砸塌 4 列。                              |
|  [再来一轮] [换个模式] [看看画面]                |
+-----------------------------------------------+
```

- **评语三档**（`低 / 中 / 高`）阈值在 `js/app.js` 头部：
  `{cpm:180, acc:0.95}` → 高，`{cpm:90, acc:0.88}` → 中，其余 → 低。
  速度与正确率**两档都要达标**才算上一档。
- 行数据由 `buildSummary()` 组装成 `[键, 值]` 数组，`menu.showSummary()` 只管渲染，
  **不做任何计算**。
- 一个都没击破时，`text` 换成鼓励文案（"一个都没打中就结束了。先按对最下面那个
  气球试试。"），不显示毫无意义的平均反应。
- 三个按钮：`#summary-again` 再来一轮 · `#summary-menu` 换个模式（关浮层、
  开菜单的模式页）· `#summary-close` 看看画面（只关浮层，保留结算前的画面）。
- **Esc 关掉的是结算浮层，不是菜单**——关菜单会让游戏在玩家没准备好的情况下开跑。

## 7. 提示条 (`#toast`)

底部居中的一次性消息，2.6 秒后自动隐藏。目前只用于**地面塌陷**：

```text
第 3 列塌了（2 / 4）
```

带列数与当前进度，因为塌陷发生时玩家的视线在画布上，需要一个画面外的确认。

## 8. 设计 token

`styles/tokens.css` 里除系列通用 token 外，新增两组：

### 8.1 画面区尺寸

```css
--stage-area-w: clamp(304px, 52vw, 1024px);
--stage-area-h: clamp(285px, 72vh, 960px);
--panel-width:  clamp(430px, 26vw, 560px);
```

### 8.2 NES 调色板 (`--nes-*`)

全部是**纯色、无渐变**——渲染层按 `image-rendering: pixelated` 放大，渐变会露馅。

| 组 | 变量 | 值 | 用途 |
|---|---|---|---|
| 天空 | `--nes-sky` | `#5c94fc` | 天幕 |
| 云 | `--nes-cloud` / `--nes-cloud-shade` | `#fcfcfc` / `#b8d8f8` | 云体与云底 |
| HUD | `--nes-hud-bg` / `--nes-text` / `--nes-text-dim` | `#000000` / `#fcfcfc` / `#bcbcbc` | 顶部信息条 |
| 墨色 | `--nes-ink` / `--nes-outline` | `#000000` | 气球上的字符、描边 |
| 地面 | `--nes-grass` / `--nes-grass-dark` / `--nes-dirt` / `--nes-dirt-dark` | `#00a800` / `#007800` / `#c84c0c` / `#8c3000` | 草皮与泥土断面 |
| 鸟喙 | `--nes-beak` | `#fce438` | 小鸟的喙 |
| 气球 | `--nes-balloon-0` … `-7` | 红/橙/黄/绿/天蓝/紫/粉/白 | 8 种球色 |

球色按色相拉开，保证**相邻球在灰度下也分得清**（色盲友好）。

**改配色只改这一个文件**——`js/ui/stage.js` 里不出现任何硬编码色值，
所有颜色经 `readPalette()` 从 `:root` 读入，每个字段都有兜底默认值
（样式表没加载完时不会黑屏）。

## 9. 交互细则汇总

| 操作 | 行为 |
|---|---|
| 键盘字母/数字键 | 进入 `press()`，命中则 `preventDefault()` |
| 方向键 / 功能键 / F5 等 | 被 `/^[a-z0-9]$/` 白名单挡掉，不计失误 |
| 中文输入法 | `key === 'Process'`，同样被挡掉；「玩法说明」页提示切输入法 |
| `Ctrl`/`Meta`/`Alt` + 键 | 直接 return，不劫持浏览器快捷键 |
| 空格 | `preventDefault()`，不让页面滚动 |
| 菜单/结算浮层打开时 | `keydown` 不进入游戏 |
| 切到别的标签页 | `visibilitychange` → 暂停，逻辑时钟停在原地 |
| 切回标签页 | 自动恢复（菜单没开的话），`acc` 清零避免补步 |
| 首次点击/按键 | `unlockOnce` 建 AudioContext，更新 `#hint-audio` |
| Esc（结算浮层开着） | 关浮层 |
| 窗口 resize | `ResizeObserver` + `window.resize` → `fitStage()` 重算整数倍 |

**暂停的语义**：`state.clock` 停在原地，回来接着走。不会出现"去倒杯水回来
地面已经塌完了"。

## 10. 响应式

- 主区 `.game-layout` 用 **CSS Grid**，默认单列（`grid-template-columns: 1fr`），
  侧栏自然落到画面下面。
- **断点只有一个**：`@media (min-width: 1200px)` 时切成
  `minmax(304px, auto) var(--panel-width)` 双栏。这个值取的是
  「画面区最小宽度 + 侧栏宽度」之和再留余量——否则 1100px 附近会横向溢出。
- 画面区高度用 `vh` 参与 `clamp`（`--stage-area-h`），所以矮屏上会自然缩到
  1x 或 2x，不会把侧栏挤没。
- 缩放的**上下限**由 `stage.resize()` 的 `max(1, min(4, ...))` 兜底：
  极小窗口退到 1x（仍然整图可见），极大窗口封顶 4x。
